# Embedding, Vector & Graph Database Explainer

> Keep the facts in SQL, use vectors to find relevant meaning, and reach for graphs when the relationship path itself matters.

Local HTML diagram explaining the relationship between embeddings, vector databases, and graph databases.

**Local file:** `~/.agent/diagrams/embedding-vector-graph-database-explainer.html`

## Key Points
- Embeddings compress meaning into vectors so semantically similar text lands near each other, but the original text still needs to stay available.
- Vector search answers "what feels similar?" while graph databases answer "how is this connected?"; they solve different retrieval problems.
- The practical pattern is to keep canonical facts in SQL and add embeddings or graph models as specialized retrieval layers.
