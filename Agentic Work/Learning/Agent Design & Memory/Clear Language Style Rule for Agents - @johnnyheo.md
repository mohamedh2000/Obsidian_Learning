## Key Points

- Fable and Sol tend toward dense jargon that slows first-read comprehension; a style rule fixes it.
- The rule: write user-facing explanations in clear, concise language without reducing technical precision — prefer concrete wording, use domain terms when most precise and briefly define them for the audience, and preserve evidence, constraints, tradeoffs, caveats, and uncertainty.
- Carve-out: do not rewrite code, identifiers, commands, quoted text, or prescribed formats just to satisfy the style rule.
- Pair it with `personality = "none"` in `~/.codex/config.toml`.
