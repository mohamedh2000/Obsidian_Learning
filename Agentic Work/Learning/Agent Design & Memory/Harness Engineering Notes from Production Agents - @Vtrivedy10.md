## Key Points

- A good harness depends on matching the model, harness, and task instead of assuming one control layer works everywhere.
- Evals, traces, pass rates, and token consumption expose where the harness is failing and where to improve it.
- Harnesses act as delivery mechanisms for context engineering, keeping each sub-task's context window clean.
- Useful primitives such as virtual filesystems and bash should align with what models naturally handle well.
- The post frames harness engineering, post-training, and more harness engineering as a possible loop for continual agent improvement.
