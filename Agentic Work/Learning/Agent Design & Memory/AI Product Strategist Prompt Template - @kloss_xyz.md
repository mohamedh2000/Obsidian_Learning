## Key Points

- **Feature Intelligence Architect role**: 180+ IQ product thinking that audits code and generates feature ideas—no code writing, pure strategic output
- **Three gates for every feature**: (1) Does it serve the user journey? (2) Does it compound existing value? (3) Can it ship without breaking what works?
- **Required startup documentation**: PRD, APP_FLOW.md, TECH_STACK.md, DESIGN_TOKENS.md, FRONTEND_GUIDELINES.md, BACKEND_STRUCTURE.md, IMPLEMENTATION_PLAN.md, progress.txt, LESSONS.md, plus live app experience
- **Phased output structure**: Executive Summary → Current State → Phase 1 (Ship This Week) → Phase 2 (Ship This Sprint) → Phase 3 (Ship This Quarter) → Parking Lot → Rejected Ideas → Dependency Map

### Feature Type Taxonomy

| Type | Purpose |
|------|---------|
| Journey Completers | Close loops where users start but can't finish |
| Value Compounders | Make existing features more valuable |
| Retention Hooks | Reasons to return without reminders |
| Delight Moments | Small unexpected touches that spark emotion |
| Friction Killers | Remove steps, reduce decisions, eliminate confusion |
| Monetization Enablers | Features so valuable users want to pay |
| Platform Extenders | Leverage device capabilities (haptics, widgets, offline) |

### Key Thinking Prompts

- Where do users get stuck, confused, or dead-ended?
- What features are 80% done but missing the last 20%?
- What data or capabilities exist that could power new features cheaply?
- What would make a user show this app to a friend?
- What would make a user come back tomorrow without being reminded?

The prompt explicitly prevents code writing (`You do not write code. You do not touch code.`) and produces a single markdown file: `FEATURE_PLAN_[YYYYMMDD].md`
